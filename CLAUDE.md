# CLAUDE.md — working agreement

`azure-care-intelligence-platform` is Patient Risk & Adherence Intelligence: a readmission-risk
model on Azure Machine Learning whose headline number is **cost avoided per thousand patients
contacted**, served with a plain-language explanation per score, audited for fairness by
subgroup, promoted only through a human approval, and trained on **synthetic data only**. A
staff engineer reads it for ten minutes and must conclude the author owns the full model
lifecycle, not just generative AI. That depends on **restraint**: the code that remains is only
the code that expresses a modelling or business decision.

The governing rule:

> If a capability exists in Azure Machine Learning, do not reimplement it in Python.

And its corollary for this portfolio: **no agent anywhere in this repository** (ADR-013). Nothing
here is open-ended or tool-driven; it is supervised learning on tabular data with a deterministic
serving path, and *if you can write a function to handle the task, do that instead of using an
AI agent* applies to every module.

Re-read this file at the start of every phase.

## Process

- Do not stage, commit or push. The author commits at the end of each phase with the message
  printed in the phase summary, on a `feature/<words>` branch; `main` is protected and receives
  pull requests only.
- At the end of each phase stop and print:

  ```
  ── PHASE n COMPLETE ──
  Files: <n>/60   Python: <app>/1400 + <tests>/400   Bicep: <n>/400   Comments: <n>/25
  Verified: ruff ✓  mypy ✓  pytest ✓  budget ✓
  Commit with:
    git add <paths>
    git commit -m "<message>"
  Say "continue" for phase n+1.
  ```

- Every Azure ML, MLflow, SDV, scikit-learn and PostgreSQL name is verified against the installed
  package before it is written. The names below were verified on 2026-10-20 against the pinned
  versions in `requirements*.txt`; several differ from the specification's reference and from
  older samples (noted in the table).

## Non-negotiable constraints

1. **No identity leakage** anywhere, fixtures and commit messages included. Placeholders only.
2. **Zero secrets.** `DefaultAzureCredential` for every Azure call; Entra tokens for the endpoints
   (`auth_mode="aad_token"`), PostgreSQL and the API. The workspace's Key Vault exists because
   Azure ML requires one and holds nothing this repository writes.
3. **No real patient data, ever.** Every row is generated by `src/data/synthesize.py`; the README
   says so above the fold and the model card repeats it.
4. **No Jupyter notebook is part of the system.** Notebooks live in `examples/`, are never
   imported, and the budget test asserts both.
5. **Size budget, enforced by `tests/test_budget.py`:** tracked files excluding `docs/` and
   `examples/` at most 60 (the specification says 46; its own mandated layout — twelve modules in
   five packages, four component specs plus an environment, six workflows, three experiments,
   infrastructure in modules, the API and its Dockerfile — needs more, and the README records the
   count); the specification's 1,200 lines of Python apply to the application code (`src/`,
   `pipelines/`, `api/`, `ops/`), whose per-module targets it lists; **raised to 1,400 in phase 7**
   because the specification's own serving scope (two endpoints, the scoring module, cohort
   similarity, the batch pipeline, the API and the operations scripts) is not in its 830-line module
   table, and the README records the actual count; the tests have their own ceiling of 400;
   ≤ 400 Bicep; directory depth 3; functions ≤ 35 lines.
6. **Comments.** No `#` comment may restate the code; fewer than 25 in the whole Python codebase.
   Type hints replace them.
7. **No defensive clutter.** No bare `except Exception`; ruff rule `BLE001` and the budget test
   both enforce it.
8. **Minimal dependencies**, exact pins. `sdv` and `torch` live in `requirements-synth.txt` and are
   installed only to generate the cohort; nothing in `requirements.txt` imports them.
9. **`targetScope = 'resourceGroup'`.** `rg-careintel-prod-swc` exists; never create it.
10. **English** everywhere. Nothing unfinished.

## Architecture in one paragraph

`src/data/synthesize.py` generates the cohort once and registers it as a versioned data asset.
An `@pipeline` job composes four YAML components — `prep`, `train`, `evaluate`, `register` — on
serverless compute; every metric goes to MLflow; `register` refuses a challenger that does not
beat the champion on cost avoided per thousand contacts. A managed online endpoint serves one
score with its SHAP contributions translated through deterministic templates; a batch endpoint
produces the weekly ranked call list with the expected value of each contact; PostgreSQL with
`pgvector` answers "the forty most similar patients and what worked". A drift monitor triggers
the training pipeline, which stops at the approval gate. GitHub Environments carry the model from
dev (feature branch) to staging (main) to production (named reviewer).
